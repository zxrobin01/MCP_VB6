# Changelog

> [中文](CHANGELOG.md) | **English**

User-visible changes: what changed and **why**. One rule: only what can be verified from the code or the history; unverifiable history stays unwritten. No names of unopened external products, no private project names, no maintainer machine paths appear here.

**Current: product `0.3.0` · contract `v1.16.5` · tool face: `120` (add-in) + `11` (hub) = `131` (client-visible)** - the product version comes from `Util.bas` (echoed by `initialize` and `mcp_info`). The add-in face lives inside the VB6 IDE process; the hub face runs outside it and **works with no IDE online**. On a machine the **middle service** (`bridge/vb6mcp_bridge.py`) owns **the single TCP port** (default `127.0.0.1:8767`; the add-in speaks **named pipe**), MCP clients come in through the **hub** (`bridge/vb6mcp_hub.mjs`, stdio), and **every HTTP surface requires a token once a credential is configured**. The contract version is the compatibility contract of the tool face and receipts (it rises when tools are added/removed or descriptions change; `mcp_info.breaking[]` / `migrations[]` list changes that alter how you must call). This repository ships **source only**: build `VB6MCP.dll` yourself with `build.bat`. Separately, the `.vbp` project file carries its own `1.0.0` version resource, unrelated to the two above.

This file records **source and feature** changes only; packaging, release and other infrastructure work is out of scope.

**What changed**: ① A `quit_ide` receipt with `requested:true` now carries `exitWrites{declaration,observed,condition,evidence,basis}`: it is a **declaration**, not a measurement (a process cannot observe its own exit phase). `condition` is decided only from the project count visible now: 0 projects => `no_project_observed_no_write` (measured: nothing written); 2+ => `project_group_context_then_clean_quit` (a 50~53 B `.vbg` appears about 250 ms later); exactly 1 => `undetermined` (the two measured shapes disagree). `evidence` is a fixed 4-entry list and `basis` names the source; `sideEffects.filesWritten` covers only writes during the call and **never the exit phase**. ② The contract banner in generated documentation was corrected (old v1.16.0 -> v1.16.4). **Why**: the exit phase may write a `.vbg`, and the tool can neither confirm nor prevent it; rather than promise "nothing was written", it states the condition, the evidence and the uncertainty it can actually observe.

### 14:01 · Contract v1.16.0 · behavioural breakpoint probe (two phases) · RUN-state End no longer falsely refuses · compiler authority for verify · multi-component batch edits

Tool count 120/11/131 unchanged; +7 optional parameters, `breakpoints.action` enum +probe, 9 descriptions changed, and `apply_edits`/`preview_edit` `required` moved from `["name","edits"]` to `["edits"]`; this version was re-frozen.
**Why**: native breakpoints "recorded success but never hit", and injected ones wrote the source and killed the IDE twice - only a real run that stops on the target line proves effectiveness. Lint is lexical/structural and once reported 49 errors for a large module while `/make` reported 0; the compiler must be the authority. A cross-file rename used to take a dozen single-component calls and a mid-way failure left a half-edited state.

### 10:02 · Contract v1.14.0 · ide_restart is continuable + content is one JSON document + peer_dead

**What changed**: ① `ide_restart` adds `wait_ms` (bound on how long one call blocks; default 25000, clamped 1500..300000) and `opId` (continue a previous operation); **a timeout is not a failure**: it answers `pending:true + state:"in_progress" + opId + currentStep + lastKnownState` while the restart keeps running in the background; `ide_restart{opId}` only reads the in-process operation registry (kept 30 minutes) and **starts nothing**; only one restart at a time is allowed, and a second one is refused with `restart_in_progress + inProgress`. ### 10:02 · Contract v1.13.0 · target resolution separated from offline routing + ide_start readiness + hub out-of-band reset (one new hub tool)

**What changed**: ① The default target ladder selects **live instances only**: after discovery, candidates are re-checked by pid/transport and dead ones dropped, so a stale hub record can no longer become the default target; an explicit `_target` pointing at a dead pid answers `target_mismatch` with `onlinePids[]` / `targetDiagnostic` / `howToProceed` / `suggestion`; with zero live instances an IDE-face tool answers `no_live_ide` (`reasonLegacy:"no_ide_running"`) instead of a pid-level target_mismatch. ② **Offline routing**: `build` / `make_project(route!="ide")` / `project_meta` are served by the hub with no live IDE (`offline:true + offlineRoute:"cli"|"file" + targetResolved:false`), running an isolated `VB6.EXE /make`; the LAA bit is applied and read back after compiling, and `artifact{exists,bytes,mtime,sha256}`+`artifactChanged` are sampled **after all rewrites** (`hashedAfterRewrites`+`rewriteSteps[]`); when no compiler can be started it answers `cli_unavailable`; `package_app`/`verify` explicitly say `offlineServed:false + no_live_ide`. ③ `ide_start`: `ok:true+started:true` only claims the **process was created**, while `ready:true` means the add-in was observed answering `mcp_info` for that same pid (bounded polling, never a fixed sleep); a timeout answers `ready:false + readyWaitMs + readyChecks{...} + pollingHint`; an already-open `.vbp` is reused. ④ New hub tool `ide_kill_and_relaunch`: independent of the add-in pipe, it stops an instance **this hub owns**, clears its registration, relaunches on the same project and polls readiness; the receipt carries `stoppedPid/newPid/ready/readyWaitMs/threeWay{...}`; non-owned instances, known ports below 8767 (including 8766) and remote instances are refused. Tool face: add-in 120 -> 120, hub 10 -> 11, DSH-facing 130 -> 131.
**Why**: with the IDE closed `build` was still blocked by a stale pid (offline compilation is the only path to a real compiler log); right after `ide_start` returned a pid a tool call answered `target_mismatch` (a ~10-15 s registration window); and while the pipe was busy even `release_inflight` could not be delivered, so the only exit was a manual Stop-Process. All three need "live instances only + out-of-band reset" on the hub side.

### 20:24 · Contract v1.12.0 · debug capability + write/verify/build hardening · add-in face 110 -> 120 (ten new tools)

**What changed**: ① **Ten new tools**: `debug_session` / `run_until_break` / `breakpoints` / `get_locals` / `eval_at_frame` / `run_project` / `last_error` / `move_procedure` / `delete_procedures` / `edit_by_byte_anchor` (add-in face **110 -> 120**; the hub face stays at 10, so **130** tools are client-visible). ② **Start/End are queued commands (STA)**: one call cannot cover start -> break, so it is **two-phase** (start answers `startedPending` + `howToContinue`, then attach to observe); `debug_session` never saves the project (`preRunSave=false`); an End that is still queued reports `endQueued` instead of a false `wedged` (`wedged` now means unrecoverable inside the call). ③ Breakpoints carry `paneLine` + `diskLine` + a source declaration; native breakpoints set by hand cannot be enumerated or verified (`nativeStateVerified=false`); conditional breakpoints are expressed with `hitCount`. ④ `get_locals` returns **names only** (the Immediate-window context is not a breakpoint frame, so values are unavailable: `localsUnavailable` + reason); `eval_at_frame` evaluates only in the IDE's Immediate context, refuses by default in break/run, runs only with `allowUnsafeEval`, and **statically refuses object/array expressions before evaluation** (`object_expression_unsupported` - they can hang the IDE); `timeoutMs` is only a caller-side budget hint. ⑤ `run_project` is two-phase and sets environment variables before Start; a Standard EXE started from the IDE refuses command-line arguments; an already-running `-Embedding` process cannot be attached; `last_error` returns the error dialog text + call stack + local variable **names**. ⑥ `move_procedure` / `delete_procedures` are **transactional** (snapshot + rollback); `edit_by_byte_anchor` edits **raw ANSI bytes** with GBK lead/trail boundary checks and a roundtrip self-check, and **never writes on failure** (`fileUntouched` + sha parity). ⑦ `build` / `make_project` gain `sourceFreshness` (per-component disk-vs-pane, comparing **normalised text** only), `final{}` (sampled **after** the LAA patch: hash/PE/FileVersion/`verifiedOnDisk`), `project` (cli route only) and a CLSID `InprocServer32` guard (read/restore); **a build cache hit no longer parses any log** (`logAvailable=false`, `logSuppressed`, `logOwnership.verified=false`, a stale log is only reported) - this fixes cross-project log contamination - plus `compileLogHint` + `diagnoseRecommended`. ⑧ `verify` gains `semanticDiff` (case / Attribute / trailing-space normalisation with per-line `paneLine/diskLine/category`), `failureLayers{ideDiskDiff,lint,build,modal}` and `overallBasis`; `verify_scope` counts only a **proven IDE!=disk** as a fail (`failBasis=ide_disk_diff_proven`), accepts `baseline`, and always publishes the invariant `pass+fail+unknown==checked`. ⑨ `add_component` / `remove_component` keep the `.vbp` line and the component file **atomically in sync** (the component file lands first, the `.vbp` gets exactly one trailing CRLF; both sides roll back on failure), and adding a `Form` / `UserControl` is explicitly refused (`pairedBinaryUnsupported`). ⑩ `write_file` / `write_source` refuse "existing non-empty file + empty content" (`empty_content_would_truncate`; only `confirm_truncate=true` allows it) and never write an empty VB source file. ⑪ When `dependency_graph` is `partial` it publishes `minQuotaHint{charQuota,budgetMs,basis}` (one rerun with those values reaches a complete graph) and a `completeHint` pointing at the exact arguments; when complete coverage is unreachable it reports `cannotComplete` instead of inventing one.
**Why**: this version moves **debugging** from "look at state" to "drive it": Start/End are **queued commands** on the STA, and one call cannot both start and break, so the two-phase shape plus an explicit "queued / how to continue" answer is far more reliable than a call that would never return. For breakpoints and locals, only **names and positions** can be verified (the Immediate context is not a breakpoint frame), so values come back as `localsUnavailable` rather than as a plausible-looking fake; object/array expressions can hang the IDE, so they are refused statically before evaluation. The write-class work unifies one rule - **either the whole thing succeeds or nothing changes**: procedure move/batch delete are transactional with rollback, and byte-anchor edits never touch the disk until the GBK boundary and roundtrip checks pass. On the build side, "**cache hit**" and "**this run actually compiled**" are now separated: a cache hit no longer parses the previous log (which used to feed another project's errors into this receipt), and the timeout budget is **enforced** (the child is killed at the deadline with no leftover). **Limits (stated honestly)**: local variable **values** at a breakpoint remain unreadable, object/array inspection is unreachable, any Immediate-window evaluation can hang (recover with `release_inflight`), `run_project`'s in-process read-back of environment variables is **unproven**, and UNC paths are unverified.

### 01:50 · Contract v1.11.12 · one diagnosis rule + write-order preservation + hang observability (no tools added or removed)

**What changed**: ① **One ownership rule**: `ide_list`, the forwarded `ide_state` receipt and `ide_restart` (`ide_stop` too) share **one** resolver; the receipt gains `ownershipVerdict{verdict,basis[],...}` plus the rule text, with the two axes kept apart: the legacy `ownership` / `ownedByHub` (the **permission axis** for `ide_stop` / `ide_restart`, unchanged) and the new `ownershipVerdict` (**identity axis**); **identity does not grant permission** (a user-started IDE that answers is `owned` yet stays `ownedByHub=false` and still cannot be restarted by `ide_restart`). The verdict is **owned / foreign / unknown**: `foreign` requires **positive evidence only** (a dead registered pid whose port still answers / an OS port owner that differs from the registered pid / a reserved-range port that answers / a listener pid that differs from its own registration); `unknown` covers everything else, including `portAvailable=false` (a pipe-only registration publishes port 0 on purpose); an unknown attribution makes `ide_restart` answer `refused_reason:"ownership_unknown"` + `legacyReason` + `howToDisambiguate` (refusing to restart by default). `hubInstance.ownership` is no longer `null`. ② **Write-class line order**: `apply_edits` gains `deletedLines` / `deletedText` (truncated) / `deletedTextLines` / `deletedTextTruncated` / `deletedTextLimit`; `apply_edits` and `preview_edit` refuse `delete_with_text` / `would_empty_component` with the **same reason** (preview does not report the `deleted*` keys); `reload_component` / `save_project` gain the `vbpOrder*` / `vbpRevision*` / `inMemoryOrder*` field family - **if saving changed the `.vbp` line order it must be restored** (reordering lines only, never dropping VB6's own content; a failed restore answers `ok=false` + `reason:"vbp_order_restore_failed"`); locked bounds: `vbpOrderLinesCapped` = 400 lines, `vbpOrderChanges[]` <= 50, `deletedTextLimit` = 4000 chars. ③ **Hang observability**: `make_project` gains `timedOut` / `budgetEnforced` / `budgetMs` / `budgetSource` (`timeout_ms` / `default` / `clamped_*` / `not_applicable`) / `stopReason` (four fixed values) / `stopReasonPriority` / `host_modal_blocking` / `host_modal{...}` / `isolatedMake{...}` / `budgetNote` / `timeoutNote`; `build` uses the same mechanism (on timeout `ok:false` + `verdict:"timeout"`, instead of throwing "build process failed to run"). **`ide_state` has zero tool-face changes** (no parameter/description/schema change); only behaviour: the isolated-build wait loop now pumps messages (`Util.PumpNow`), so a `depth>0` **read-only probe is dispatched during a long call** (`serviceable` means, as measured, that the read-only call was actually served).
**Why**: these three batches all fix "**the same fact gets opposite answers from different entrances**" and "**when something hangs, the receipt cannot say where**". With ownership scattered across the port, the registry and the source, one pid could be "ours" on one entrance and "foreign" on another - so the only tool designed for wedged recovery refused its own instance exactly when it was needed; one resolver, two separate axes (identity != permission) and an explicit refusal plus disambiguation steps for "unknown" make it predictable. If `.vbp` line order is reordered by a save/reload the project still compiles but the component order changes silently; making "restore the original order after saving" part of the contract (a failed restore is `ok=false`) is far cheaper than debugging it later. Hang diagnoses are hardest because "timed out and killed", "cache hit", "blocked by a host modal", and "refused by preflight" used to be indistinguishable - making them non-overlapping fields (and never letting a cache hit impersonate a compile) lets the reader of a receipt see immediately whether to rerun or change the budget.

### 17:50 · Contract v1.11.10 · Transport fix (a behaviour fix) · build evidence is PROJECT-level · one-off hygiene

**What changed**: ① `verify_scope` judges **build evidence at the PROJECT level**: `buildOk` / `buildSource` / `buildNote` come from the **project-level** build cache (both key and hash are project-level), and **a single component cannot "lack build evidence by itself"** => `unknown` is a **project-level** conclusion and `pass` is only reachable on a project with a **fresh build cache** (in a project that was never built, every component whose IDE and disk agree is `unknown`). ② **Transport fix (a behaviour fix, not wording)**: three winsock transport defects are fixed - (a) the **per-connection object was never persisted**, so a request arriving in more than one TCP segment **lost its head** and was only dropped by the 30 s idle sweep; (b) **close-after-send was decided after the queue had already been cleared**, so a `Connection: close` response lingered until the idle sweep; (c) the **flush path grew a cumulative `Mid$` start past 64 KiB**, and `send()=-1` together with `WSAGetLastError()=0` was treated as fatal => bodies were truncated at 64/96 KiB. ### 22:13 · Contract v1.11.3 · dependency graph: a deterministic quota + honest truncation

**What changed**: the main deadline of `dependency_graph` moved from **wall clock** to a **deterministic character quota** (`VB6MCP_CHAR_QUOTA`, default **900000**, counted as characters processed), with a **reserved share** per phase (tokenize / component edges / purity / cycles+procedure edges) so the default setting **always produces procedure edges**; the wall clock became the **last resort** (`VB6MCP_BUDGET_MS`, default 30000) and is reported through its **own** field `timingTruncated` - `budgetExhausted` means the quota was reached, and the two are not the same thing. **Honesty**: `procEdgeStageCompleted` was added; `partial` now means "some phase did not finish"; the four `*StageCompleted` flags are `false` whenever that phase **or its input phase** was truncated; `componentsTotal` is now the **project's real component count**; `componentsScanned` counts only components that were **tokenized completely**. **Determinism**: calling twice on the same input returns an **answer that is byte-identical**; only envelope fields (self-timing, session identity) may vary. Tool face: **no additions or removals**, `inputSchema` **byte-identical**; the only change is the `dependency_graph` **description** => explicit re-freeze.
**Why**: the old implementation decided where to cut by wall clock - across three consecutive calls on unchanged source the procedure-edge count drifted, and on a large project it jumped between "no edges" and "thousands of edges"; worse, a truncated phase **still reported itself complete**, so the default run delivered a graph with nodes and no edges. With a deterministic quota the same input always stops at the same place, and "did not finish" is reported as such. **Known limitation**: for very large projects the **complete graph cannot be delivered in one call** (raising both the character quota and the wall-clock budget is required; pagination comes in a later version).

### 16:34 · Contract v1.11.2 · source stamp

**What changed**: `mcp_info.build` gained two **additive** fields: `sourceHash` (a deterministic fingerprint of the source input set) and `sourceAlgo` (the algorithm identifier). **Tool face unchanged**: `tools/list` names, descriptions and parameters are byte-identical, and the four frozen artifacts are **not re-frozen**. Semantics: **identical code => identical fingerprint** (across runs and machines; the binaries themselves may differ with the build environment), and the **reverse is not promised** (a source change the compiler ignores should still produce the same artifact). The algorithm identifier moved from `vb6src/1` to `vb6src/2`: before hashing the `.vbp` it **masks the values of four version keys** (`MajorVer`/`MinorVer`/`RevisionVer`/`AutoIncrementVer`, keys kept), so the fingerprint **no longer drifts** when the compiler writes an auto-incremented version back into the `.vbp`; the artifact version is now reported and compared **separately**, and a version difference **does not affect** the verdict.
**Why**: build verdicts used to come from string-scraping the artifact - the same source built in different environments yields different binaries, so "did the source change" was unverifiable. Turning the **source input set** into a receipt field lets a caller check **source identity**; the version keys were masked out because one `/make` **rewrites its own input** (the version auto-increments), which made the old algorithm read "the source did not change" as "the source changed".
## 2026-10-14

### 23:30 · Contract v1.11.1 · bounding and guidance corrections · the dependency graph and the public-API tools can no longer wedge the host

**What changed**: (1) **`dependency_graph` and the two public-API tools (`export_public_api` / `check_public_api`) now run under one wall-clock budget** (default **8000 ms**, overridable with the `VB6MCP_BUDGET_MS` environment variable); when the budget is spent the scan **stops and returns what it has**, and the receipt always carries `budgetExhausted` / `budgetMs` / `elapsedMs` / `stage` (`dependency_graph` also adds `tokenizedComponents` / `edgeScannedComponents`; the two API tools add `scanned` / `componentCount`). (2) each of the two API tools gained an **optional** parameter **`membersOnly`** (default `false`): when true it returns only the member list (`kind` / `name` / `sig`) and **skips generating the spec / violations text and the second parse that came with it**. (3) the **`name` of both API tools may now be omitted**: omitting it performs a **bounded** whole-project export / check (per-component counts + `scanned` / `componentCount` + `budgetExhausted`) instead of an unbounded scan. (4) the component-edge phase of `dependency_graph` changed from **a whole-text match for every pair of modules** to a **single-pass membership test** - each module is tokenized once and looked up against a lowercased name table. (5) tool face: **add-in 110 -> 110**, hub **10**, client-visible total still **120**: **no tool was added or removed**, the new parameters are purely additive and the defaults are unchanged. (6) **non-functional wording fix**: the `validate_code` description no longer calls itself "a local rule engine"; it now states that it **runs inside the add-in, requires a live IDE and is not an offline check**. (7) the hub-side **forwarding-failure classification** landed with this batch: `noIde` (nothing to talk to: no live IDE, no usable route), `wedged` (the connection was accepted but the peer timed out or went away, or every discovered instance failed its probe), and `toolError` (the IDE did answer, and that answer is itself a structured error) - callers no longer have to guess from raw transport errors.
**Why**: the component-edge phase used to grow with the **square of the module count** - with many modules every pairing re-matched the whole module text, i.e. tens of thousands of full-text scans; on a project at the **200-component scale** the call was measured **never returning** while the CPU stayed busy, dragging the host down so that even read-only status queries had to queue. With the single-pass test the same project returns in about **8.5-11.7 s**, and the following read-only status query takes about **47 ms** while the window stays responsive. With no component name the two API tools used to scan the whole project **unbounded**, which could likewise exceed the client's call timeout; giving them the same budget and making `name` optional turns "whole-project export" into a **bounded capability with visible progress** instead of a call that can wedge. `membersOnly` is purely additive: off by default, and it only saves a parse and a large block of text for callers that want the member table alone. The wording fix is motivated by measurement: callers had used `validate_code` as an **offline check** - its description must state the real precondition (a live IDE), or the caller's expectation and the fact diverge.

### 20:31 · Contract v1.11.0 · tool face 115 -> 110 (add-in) · the five lesson tools move to the hub face · the IDE addressing key is the .vbp path · explicit remote-endpoint allow-list

**What changed**: (1) **the five lesson tools moved to the hub face** (`list_lessons` / `add_lesson` / `delete_lesson` / `export_lessons` / `import_lessons_md`): name, description and parameters are **unchanged word for word**, so calls look the same; the implementation moved to the Python side (`tools/lessons.py`) and the data stays `mcp_lessons/defaults.json` + `mcp_lessons/user.json` (same schema, an existing `user.json` carries over as-is). Hence **add-in face 115 -> 110**, **hub face 5 -> 10**, and the **client-visible total is still 120**. (2) **the IDE addressing key is now the `.vbp` path instead of the pid**: the canonical form is `_target = "[endpoint:]<drive>:\<dir>\project.vbp"` (endpoint omitted = local); a bare `pid`, a bare project name and `auto` still work, but only as **legacy aliases** and are no longer reported as the canonical key. Paths are normalized case-insensitively, `\` and `/` are equivalent, trailing separators are trimmed, and a local path that exists is additionally resolved to its real path; when one selector matches several identities the call is **refused structurally** (`target_conflict`) with the candidates listed - it is **never resolved to one for you**. (3) **a call without `_target` is no longer auto-routed to a remote**: only when **no local IDE is live while a remote one is** does it return the structured `remote_requires_explicit_endpoint` (`routed:false`, with endpoint-qualified keys you can paste verbatim); with a live local IDE it still selects automatically. (4) **remote endpoints come only from an explicit allow-list** (the `VB6MCP_REMOTES` environment variable or `bridge/hub_remotes.json`): the hub **probes only the listed endpoints and never discovers hosts on its own**; with nothing configured every remote code path is inert (behaviour identical to before the change). Failures are always structured: `endpoint_unknown` (a name that is not configured) / `endpoint_unreachable` / `endpoint_timeout`.
**Why**: the lesson store is a **global singleton** that does not belong to the IDE on any one machine - keeping it in the add-in made the whole capability disappear whenever **no IDE was online**, and made **changing one lesson require rebuilding the add-in**; moving it outside means it **works with no IDE online**, and changing a lesson is just editing a JSON data file that is read at runtime. A pid is an identity that **changes on every launch**, so a remembered default target could point at an instance that no longer exists; the `.vbp` path is the project's stable identity and the only key that can express both "two different projects on one machine" and "the same path on two machines" (the latter is separated by the `endpoint` prefix). The old rule "with no target, pick the only live instance" would, once remotes existed, **silently send a call to another machine**; now automatic selection only ever stays local, a remote must be named explicitly, and "only a remote is online" became a readable refusal code. Since a remote host has to be configured explicitly, it must not be auto-discovered: no address exists outside the allow-list, probing targets only the allow-list, and failures carry a structured reason and elapsed time.

## 2026-10-13

### 16:26 · Tool face 114 -> 115 · live desktop state · long code can come from a file · one failure envelope

**What changed**: added a read-only tool **`desktop_probe`** that reports the **live** desktop state of the process hosting the add-in (window station / desktop / session / foreground) and **refuses honestly** (`ok:false` + `failureKind`) when an API cannot be read, instead of returning a zero-filled picture; `vba6_probe` / `immediate_eval` / `immediate_run` each gained one **optional** "read it from a file" parameter (`exec_line_file` / `expression_file` / `code_file`); `vba6_probe` failures now use a **uniform envelope** (`ok` / `failureKind` / `reason`) and report the **requested vs clamped length**, and an out-of-range argument is a structured `arg_out_of_range` instead of a raw overflow; `ui_text` gives clearer diagnostics when a self-drawn panel cannot be read; **internal labels were purged from the public tool descriptions**.
**Why**: the desktop / session state had **no tool at all**, so callers could only guess; long or quote-heavy code was regularly broken by command-line length and quoting rules; without a uniform failure reason a caller cannot tell "bad argument" from "engine unavailable"; internal labels in descriptions put unverifiable text on the public surface. A previously reported claim that the foreground value "always reads 0 on this machine" was **disproved by measurement** and is corrected everywhere: desktop state is now reported as a **live value**, and send-input capability is **never** inferred from a window-station name. Note that the **Immediate-window body text still cannot be read** (that pane exposes no readable body), so **no** tool was added for it and the limitation stays documented.

### 15:08 · Compilation no longer hangs · tighter defaults in the snapshot and audit scripts

**What changed**: the modal guard now **restarts its deadline whenever it sees a box**, and the compile path's deadline covers the **whole call** => compilation no longer hangs but returns a structured result (the IDE box is dismissed with a safe button); the tool-face snapshot script now **writes no file by default**, and the strict audit script **requires an explicit target** and **refuses the machine's reserved port**.
**Why**: while compiling, the IDE pops its own "Make Project" box, and that box appears **later than the guard deadline** => the call never returned; the snapshot script used to **overwrite the contract baseline** by default; the audit script's default target happened to be the **machine's reserved port**.
### 14:50 · Breakpoint line pre-check · modal safety guard

**What changed**: before toggling a breakpoint the tool now **checks whether that line allows it** (if not it **refuses structurally** instead of triggering the IDE error box); added a **modal safety guard** - when a call is blocked by a modal box the IDE itself popped up, it **clicks only safe buttons** and **reports honestly** (the box content, which button was clicked, elapsed time, side effects).
**Why**: toggling a breakpoint on a line that does not allow it made the call **hang for about a minute** and left every later write operation answering busy; an accidentally triggered throwing statement could also pop a modal box and **stall the whole tool chain**.
### 14:23 · The wheel works immediately in a newly opened code pane

**What changed**: after a **new code pane** opens, the **mouse wheel now works immediately** (no need to click elsewhere first); this comes with a **250 ms lightweight hook timer** and per-window hook diagnostics.
**Why**: the only driver that used to hook new panes was a **5-second watchdog** (measured: 2 scans in 10 seconds) - so for a few seconds after a new window opened the **wheel was bound to do nothing**, then recovered on its own.
### 14:04 · In-process execution and read-back · session-level quiet mode · forced gate release

**What changed**: added an **in-process execution and read-back** capability (**returns values directly and captures output**, so callers no longer have to write a file to get data out); added a **session-level quiet mode** (suppresses tools stealing the foreground); when a call is stuck on one of the IDE's own modal boxes, the **gate can now be force-released** so later calls recover.
**Why**: runtime acceptance used to require **a human watching the IDE Immediate window**; a tool stealing the foreground can drop the user's **in-progress keystrokes into the code pane**; a single accidentally triggered throwing statement could **lock the whole tool chain** with no way to recover.
### 13:29 · Cumulative line numbers · operation receipts and refusals · foreground and pane protection · conditional-compilation arguments

**What changed**: component disk line numbers now **accumulate per line** (no longer too low when hidden inline Attribute lines exist); the "delete control" and "open project" receipts now carry a **success flag, before/after counts and the memory-vs-disk difference**, and **refuse structurally** when it is unsafe; tools that touch the caret or a pane now **report and restore the foreground**, and **verify the pane text is unchanged** across the operation; conditional-compilation argument values are **no longer quoted**, and the receipt shows the actual command line.
**Why**: a low line number can silently edit the wrong line; "looks successful" or "silently ineffective" makes callers misjudge; when the user is typing on the same machine, stealing focus can drop keystrokes into the code pane and corrupt the source; quoting silently disables the conditional-compilation macro.
### 10:05 · `remove_trace` no longer removes `modMcpTrace`

**What changed**: `remove_trace` deletes only the injected trace block; it no longer deletes the `modMcpTrace` module.
**Why**: that module may contain code you added yourself, and other places in the project may still use it - deleting it would lose code or break the build.

### 09:53 · Public docs no longer cite an unverifiable external product

**What changed**: the READMEs and a code comment no longer cross-reference an unopened external product; the example config now uses a placeholder path.
**Why**: readers cannot check that external reference, so it only confuses; a hard-coded local path cannot be used by anyone else.
